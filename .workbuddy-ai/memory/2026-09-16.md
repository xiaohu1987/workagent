# 2026-09-16

## 接口卡片「编辑调用」新增 JSON 入参模式

需求：设置 → 知识与记忆 → 接口卡片，展开「编辑调用」后，入参区域除现有「控件模式」外，新增「JSON 模式」。

改动文件：
- `apps/desktop/src/renderer/cards/api-card.ts`
  - 新增 `ApiCardInputMode`（`controls` | `json`）、`apiCardValuesToJsonObject`、`serializeApiCardValuesToJson`、`parseApiCardValuesJson`。
  - 负责控件取值 ⇄ JSON 原生值的双向映射（switch→boolean、checkbox→string[]、keyvalue→对象、json/number 尝试解析），并复用 `findForbiddenKey` 拦截 `__proto__` 等危险键；未声明的键收集进 `unknownKeys` 而不是静默丢弃。
- `apps/desktop/src/renderer/cards/api-card-message.tsx`
  - `ApiCardMessage` 内新增 `inputMode` / `jsonText` / `jsonError` / `jsonUnknownKeys` 状态。
  - 入参区加标题行 + 分段切换（`api-card-mode-switch`）；`config.fields` 为空时不渲染切换。
  - 切 JSON 时把当前取值序列化；切回控件时先校验，JSON 非法则阻止切换并提示；提交时在 JSON 模式下重新解析，解析结果同时写回 `values`。
  - 字段级校验错误（`fieldErrors`，排除 `__auth`）在 JSON 模式下集中回显。
- `apps/desktop/src/renderer/cards/api-card-message.css`：新增 `.api-card-input(-head/-title)`、`.api-card-mode-switch/-option`、`.api-card-json-input/-hint/-errors`，并补进 reduced-motion 列表。
- `tests/api-card.test.ts`：新增「入参 JSON 模式」8 个用例（序列化、回填、驱动请求构建、往返稳定、非法输入、未定义键、空文本、必填拦截）。
- `tests/api-card-message-modes.test.ts`（新）：`renderToStaticMarkup` 冒烟测试，覆盖默认控件模式、模式入口存在、无字段时不渲染切换、非法配置只渲染错误块。

设计取舍：
- 未给 `ApiCardMessage` 加开关 prop，因此聊天里由模型渲染的接口卡片同样获得 JSON 模式；控件模式仍是默认。
- JSON 模式只覆盖 `config.fields` 声明的入参（与控件模式 1:1），请求地址与授权仍走控件；未声明的键不参与调用，只做提示。
- 不改动 `buildApiRequest`，JSON 解析结果按字段类型回填成 `ApiCardValues`，因此类型化模板替换（number/switch/checkbox/keyvalue/json）行为完全一致。

验证：
- `npx tsc -p apps/desktop/tsconfig.json --noEmit`：改动文件零错误（仓库其余位置存在既有报错）。
- `npx vitest run`：1144 passed；仅 `tests/git-service.test.ts` 4 个用例因 git 操作超时失败，与本次改动无关。
- 预览页：`artifacts/api-card-input-modes-preview.html`，内联 styles.css 的 `:root` 主题变量 + form-controls.css + cards/api-card-message.css，保证与真实样式一致。

## 追加：一致性与校验收尾

- **一致性修复**：`switchInputMode` 从 JSON 切回控件时，原本用 `{ ...current, ...parsedJson.values }` 合并，会把 JSON 里已删掉的字段保留下来，与提交时的口径（整体以 JSON 为准）不一致。改为 `setValues(parsedJson.values)` 整体替换，并顺手清掉 `fieldErrors`。
- **类名覆盖自检**：新增 8 个类名（`api-card-input` / `-head` / `-title`、`api-card-mode-switch` / `-option`、`api-card-json-input` / `-hint` / `-errors`）在 CSS 中均已定义。`api-card-message.tsx` 里另有 `api-card-url-control`、`is-plain` 两个类名在 CSS 中无定义 —— 经 `git diff` 确认是**既有代码**，未改动。
- **预览页重构**：拆成 `artifacts/api-card-input-modes-body.html`（标记 + 切换脚本）与 `artifacts/api-card-input-modes-shell.css`（外壳样式），由通用脚本重新生成，便于后续样式变更后一键重建。
- **沉淀为技能**：`~/.workbuddy-ai/skills/codexh-renderer-ui-change/`，含 `SKILL.md` 与两个脚本 —— `gen-css-inlined-preview.mjs`（把真实样式表内联成独立预览页）、`check-class-coverage.mjs`（TSX 类名 ↔ CSS 选择器覆盖检查）。踩到并已修掉的坑：`--css/--source` 原本只吃一个取值，改为遇到下一个 `--flag` 才停。
- **环境结论**：`agent-browser` 未安装（需约 500MB Chromium），静态样式类改动用上述两个脚本替代截图；测试环境是 node 无 jsdom，组件只能做 `renderToStaticMarkup` 冒烟，交互逻辑必须抽成纯函数才可测。
- **基线**：全量 `npx vitest run` = 1152 项，4 项失败全部来自 `tests/git-service.test.ts`（git 操作在沙箱内超时，`Test timed out in 5000ms`），与渲染层改动无关；`npx tsc -p apps/desktop/tsconfig.json` 全量存在既有报错（main/storage.ts、App.tsx、packages/* 等），需按文件名过滤判断。

# 缓存前缀兼容与回退说明

## 能力边界

缓存由上游模型服务或网关决定；客户端只能保持请求前缀稳定并解析对方返回的用量，不能强制启用缓存，也不能从输入 token 总量推断命中数。

| 协议 | 已识别的缓存用量字段 | 注意事项 |
|---|---|---|
| OpenAI Chat / OpenAI-compatible | `prompt_tokens_details.cached_tokens`；部分网关提供顶层 `cached_tokens` | 网关可不返回明细；缺字段不等同于真实零命中。 |
| OpenAI Responses | `input_tokens_details.cached_tokens` | 需区分 Responses 的 `input_tokens` 与 Anthropic 同名字段；响应没有 `input_tokens_details` 时不能计算缓存命中。 |
| Anthropic Messages | `cache_read_input_tokens`、`cache_creation_input_tokens` | `input_tokens` 是未缓存输入，完整输入需把 cache read/write 计入。 |
| Gemini | `cachedContentTokenCount` | 仅当响应包含该字段时才有可观测命中量；不同兼容网关可能省略它。 |
| DeepSeek及其他兼容网关 | 依实际采用的 Chat/兼容响应字段 | 不假定模型名称能代表网关的缓存支持或用量披露能力。 |

## 显式缓存参数的启用策略

客户端只在供应商明确支持的协议上携带缓存路由或缓存控制参数，其余协议保持“仅依赖前缀稳定”：

| 协议 | 当前状态 | 说明 |
|---|---|---|
| OpenAI Responses | 已启用 `prompt_cache_key` | 键由线程 ID 稳定派生（`ProviderTurnInput.cacheAffinityKey`），重试、工具回合与恢复会话沿用同一个键，不接受网关重写。回归用例：`sends the thread cache affinity key as Responses prompt_cache_key only`。 |
| OpenAI Chat / 兼容网关 | 不发送新字段 | 依 2026-09-24 决定保持“仅前缀”；探测式启用（同 payload 双发比对 cache_read 后再条件启用）记录为后续可选方案，未实现。 |
| Anthropic Messages | 暂不启用 `cache_control` | 依 2026-09-24 决定本阶段不插入缓存断点。若后续启用，断点不得多于 4 个，并需先核对缓存写入计费语义。 |
| Gemini | 不使用显式 `cachedContent` | 显式缓存需要额外上传与 TTL 管理，本阶段只记录隐式缓存的最低长度阈值。 |
| DeepSeek | 不发送新字段 | 依赖其自动缓存行为，不假设网关会因此披露命中计数。 |

## 指标解释

- 命中、未命中与写入是上游 usage 的解析结果；字段明确返回数值 `0` 才可解释为已上报零值。
- 缓存字段缺失、协议未披露或解析无法识别时，缓存命中率应解释为“未知/未提供”，而不是“真实未命中”。旧版持久化记录若无字段存在性元数据，无法事后可靠地区分这两种情况。
- 各协议的 token 口径不同。Anthropic 的输入总量包含缓存读写，而 OpenAI 常以 `input_tokens` 报总量；跨供应商比较前需确认分母定义，不能把比例直接视为统一计费口径。
- 命中率通常按 `cached / input` 展示，但必须以该协议及供应商的 usage 定义为准。异常地出现命中量大于输入量时应标记为数据口径异常，不据此计算负未命中或超过 100% 的命中率。
- 请求前缀字节一致性与供应商账单命中是两项独立观测：前者只能说明客户端重用了相同前缀，不能证明请求到达同一缓存节点或缓存有效期仍在。

## 安全验证与故障排查

1. 按固定模型、供应商、协议、工具集合和会话模式，重复同一请求条件；分别记录协议、请求前缀哈希/长度及 usage 字段存在性。禁止记录 API key、完整提示词或业务正文。
2. 检查压缩状态、模型/供应商路由、MCP 与技能工具集合变化。它们改变时，请求前缀可能合理变化；不要为追求命中率删除安全规则、工具说明或必要上下文。
3. 若 usage 未含缓存字段，查供应商账单或供应商文档确认是否支持并披露缓存计数；本地无法补算真实命中数。
4. 若稳定前缀仍无账单命中，确认缓存窗口、账号/区域/节点分流及服务端缓存策略；在相同条件下对照一个会披露缓存用量的供应商。

## 回退清单

如稳定前缀改动导致工具调用、压缩恢复或模型行为回归：

1. 回退仅涉及请求组装稳定排序或冗余提示词 schema 副本的改动；不要回退与其独立的协议 usage 解析修复。
2. 逐项恢复原请求组装，再运行 agent-runtime 与 provider-adapters 相关测试；确认工具调用、压缩以及恢复路径正常后再发布。
3. 回退不得启用未经供应商确认的缓存参数，不记录原始请求体，不更改权限、安全提示或用户可见语义。
4. 若问题仅为缓存计数缺失，应保留“未知/未提供”诊断并向供应商核验，不以 `0` 覆盖未知值。
